# 使用教程：从打开面板到投出第一篇

面向第一次使用的操作者。每一步都说明**点哪里、看到什么算正常、看到什么该停下来**。
概念与实现细节见 [README.md](./README.md)，版本变更见 [CHANGELOG.md](./CHANGELOG.md)。

> 本文里的作品 ID、任务 ID 都来自真实运行，仅作示例；你自己的会不同。

---

## 0. 开始之前（一次性准备）

| 需要什么 | 怎么确认 | 缺了会怎样 |
|---|---|---|
| DSH 里装了本插件 | 左侧导航出现「稿定投稿」 | 没入口 |
| 装了 `dsh-image-gen` | 面板自检里「DSH 图像插件」为 ok | 没有订阅登录/出图界面，只能走 GD CLI（稿豆） |
| 该插件已登录订阅账号 | 自检里「出图能力（0 稿豆）」为 ok | 全自动会停在等待素材 |
| 浏览器已登录稿定 | 自检里「稿定浏览器登录态」为 ok | 读不到话题、投不了稿 |
| Python + ego-browser | 自检里对应两项为 ok | 创作/投稿按钮会被禁用 |

**打开面板的第一件事就是看自检条**：

- 一行绿字「环境自检通过：8 项依赖就绪」→ 可以往下走；
- 出现红字「有 N 项依赖缺失，创作/投稿已禁用」→ 按每条的「→ 修复建议」处理，处理完点「重新检查」；
- 橙色只表示「可用但有需要留意」，不拦你操作（例如没装 GD CLI、没登录订阅）。

---

## 1. 选话题

1. 进「话题与规范」标签页。列表是实时的创作者中心目录，顶部显示条数、更新时间、完整性。
2. 用搜索框或类型筛选（热门话题 / 活动 / 素材…）找到目标话题。
3. 点话题看右侧规范：画布尺寸、禁止项、创作方向、配图要求。
4. 决定做这个 → 点 **「用这个话题创建创作任务」**，会跳到创作页并带上方向与规范。

**判断标准**：如果列表显示「目录不完整 / 读取失败」，不要继续。用固定几项冒充实时目录会让稿件方向错。

---

## 2. 写 prompt

创作页顶部是任务卡，包含：数量、模式、出图后端、以及每个单元的 prompt。

### 两种模式

| 模式 | 适合 | 行为 |
|---|---|---|
| 手动 | 想逐条把关 | 生成 prompt 后停下来等你确认，确认才出图 |
| 全自动 | 批量、信任模板 | prompt 自动确认，一路跑到投稿完成 |

### prompt 怎么看、怎么改

- 每单元默认**收起**，显示「单元N · 方向 · 字数 · 两行摘要」；
- 点「查看 / 编辑」展开文本框，改完点「保存这一单元的 prompt」；
- 确认后文本框变只读——这是故意的：确认过的 prompt 不允许再变，否则出图和审核对不上。

### 什么时候该自己改 prompt

- 画面里出现**文字**要求（模板的文字是原生文字层，由排版负责，不该让模型画字）；
- 要求了**具体品牌/logo/真人照片**（平台审核会拒）；
- 方向太泛（「好看一点」）——补上画面主体、配色、留白位置、光线。

---

## 3. 出图（素材从哪来）

模板需要多层素材（背景、容器、主体、装饰），素材稿只需一张图。三种后端：

| 后端 | 面板显示 | 成本 | 说明 |
|---|---|---|---|
| DSH 出图 | `DSH 出图（0 稿豆）` | 订阅额度 | 插件复用 DSH 已登录的订阅凭据自己出图，约 20 秒/张 |
| 本机 GD CLI | `本机 GD CLI` | 稿豆 | 走 gaoding 的 Seedream，需要本地装 CLI |
| 交给 Agent | `交给 Agent` | 取决于 Agent | 插件写好素材请求后停住，由对话里的 Agent 出图 |

**推荐默认用 DSH 出图**。全自动模式下它是唯一能做到「无人介入」的后端。

### 出图过程中会看到什么

- 单元状态「等待出图素材（素材 3/8）」——正在逐张生成，正常；
- 生成完自动做两件事：缩放到目标尺寸、**白底自动抠透明**（四角接近纯白才触发）；
- 素材不合格（尺寸不对、要求透明却没有透明通道）会被拒绝并说明原因，不会带着白图投稿。

### 卡在「等待出图素材」怎么办

1. 看自检里「出图能力」是否为 ok；不是 → 去 DSH 图像插件登录订阅账号；
2. 后端是「交给 Agent」→ 这是设计如此，需要 Agent 出图；
3. 处理完点任务卡上的「继续自动投稿」，已生成的素材会被复用，不会重复花钱。

---

## 4. 创作：模板还是素材

| 类型 | 产物 | 后续 |
|---|---|---|
| 模板 | 可编辑 PSD（原生文字层 + 独立图片层）+ 预览图 | 导入稿定编辑器发布 |
| 素材 | 单张图片（PNG，按需透明底） | 直接发布到素材库 |

模板在渲染前会过一道道**质量门**，不达标直接拒绝而不是发出去丢人：

- 文字必须在 60px 安全边距内（超了自动收进来）；
- 字号 ≥24px、层级 ≤4 档、主标题 ≥ 正文 1.6 倍；
- 文字与底色对比度：大字号 ≥3:1、小字号 ≥4.5:1；
- 背景铺满画布、主体 ≤35%、除容器外不得压字、图层 ≤16；
- 纯色小色块装饰直接丢弃（它们看起来像渲染错误）。

被拦下时任务会显示「版式不合格：…」，改 prompt 让它换个排布再跑即可。

---

## 5. 投稿前检查

进「结果与投稿」页，左侧选一个产物，先看预览和「检查」结果：

- 模板检查：图层结构、文字是否原生、图片层来源是否可声明、画布尺寸；
- 素材检查：尺寸、透明底、哈希记录。

**不通过就别投**。检查项都带具体原因，例如「贴纸类素材有透明背景：alpha 232–251」意味着图不是真透明底。

---

## 6. 投稿

### 单件

点「创建投稿任务」→ 在任务上点「开始投稿」。过程约：

- 素材稿：1–3 分钟；
- 模板稿：4–6 分钟（编辑器导入 → 渲染 → 发布 → 声明会话）。

运行中任务会显示当前步骤与已耗时。**不要重复点**，同一任务不会并行。

### 版权声明（必须完成，否则不算投完）

- 模板：发布成功后的「去完善」里完成声明，插件会按来源把候选归到「原创 AI 素材」（含 AI 图层）或「原创素材」（纯程序绘制），上传证据后提交；
- 素材：声明面板上传证据 → `declaration-verified: SUBMITTED`；
- 两种情况都会**回读平台记录**核对条数，对不上就报错，不会假装成功。

完成时任务状态是 `published` + `declarationStatus: SUBMITTED`。

### 批量

1. 勾选待投稿任务（或点「全选待投」）；
2. 点「批量投稿」；
3. 或用发布队列：点「全部待投依次投稿」，出现队列状态条。

队列特性：串行执行、单件失败不中断、可「停止（当前件跑完即停）」、剩余可「续跑」。状态落盘，DSH 重启不丢。

---

## 7. 看结果

「已投稿」页读平台发布管理（自动翻页取全量）：

| 显示 | 含义 |
|---|---|
| 已通过 | 平台审核通过（`audit_cqc_status=1`） |
| 审核中 | 排队等审核（≠ 通过） |
| 审核不通过 | 被拒，行内会显示原因 |
| 待声明 | 发出去了但声明没完成 |

- 点状态徽标直接筛选；
- 可按时间 / 浏览 / 下载排序，导出 CSV；
- 每行「详情」跳平台页面。

## 8. 故障速查

| 现象 | 原因 | 处理 |
|---|---|---|
| 任务停在「等待出图素材」 | 订阅凭据缺失，或后端选了「交给 Agent」 | 自检里「出图能力」确认；登录订阅账号或换后端 |
| 创作失败「内容审核拒绝」 | 正文/负向词里有敏感分类（国旗、宗教、暴力、真实商标…） | 改 prompt 重跑；不要原样重复提交 |
| 「已有不确定提交记录，必须先对账」 | 上次发布在结果未知时中断 | 调 `POST /publish/resolve-uncertain`：平台没新作品就归档重投，有就记下作品 ID |
| 「版权声明回读不完整」 | 声明没真正提交，或候选没归完 | 看步骤日志里 `declaration-moved` 的计数；重试 |
| 「没有可归类的候选 / 候选匹配不完整」 | 声明面板还没渲染完，或平台候选数与计划不符 | 插件会中止而不是猜；重试，持续失败就查该稿是否含未登记素材 |
| 模板已发布但没声明 | 模板声明入口只在发布会话出现一次 | 用 `POST /publish/republish`（`force: true`）：确认无声明记录 → 撤销旧作品 → **重新导入设计** → 重发并声明 |
| 插件更新后页面没变 | 旧模块被缓存 | 页面顶部横幅点「立即刷新」 |
| 重装插件打断了正在跑的任务 | 重装会重建进程 | 已生成素材会复用；正在投稿那步要做对账 |

## 9. 术语

| 词 | 意思 |
|---|---|
| 单元 | 一个话题下的一份稿子；数量 2 就是两个不同方向的稿 |
| 模板稿 | 可编辑设计稿，文字是原生文字层 |
| 素材稿 | 单张图片素材 |
| 原创 AI 素材 | 声明分类：由 AI 生成的图像层 |
| contentId | 平台作品 ID，核对/修复都靠它 |
| 声明回读 | 提交后再读平台记录，确认声明真的写进去了 |
| 队列 | 发布队列，串行把待投稿任务跑完 |

## 10. 想直接调接口

面板就是这些路由的界面（详见 [README](./README.md#4-http-路由)），常用几条：

```bash
# 环境自检（?refresh=1 强制重探）
curl -s http://127.0.0.1:<port>/gaoding-publisher/preflight

# 出图自检：确认订阅凭据能出图
curl -s -X POST http://127.0.0.1:<port>/gaoding-publisher/image/test -d '{}'

# 全部待投依次投稿
curl -s -X POST http://127.0.0.1:<port>/gaoding-publisher/publish/queue -d '{"submit":true}'

# 查队列进度 / 停止
curl -s http://127.0.0.1:<port>/gaoding-publisher/publish/queue
curl -s -X POST http://127.0.0.1:<port>/gaoding-publisher/publish/queue -d '{"action":"stop"}'
```

`<port>` 是 DSH Web GUI 的端口（界面 URL 里能看到）。
