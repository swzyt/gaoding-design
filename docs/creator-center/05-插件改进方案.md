# 从创作者规则到插件改进

整理日期：2026-11-06。本章保留初始工程分析，其中“现状”指研究时的0.3版本。后续已完成0.4的动态目录、原生方案预览、文字契约、非CLI素材/登记交接与真实证据改造，具体实现及限制见[0.4优化记录](../OPTIMIZATION-0.4.md)；不能把本章所有建议视为已实现。平台事实与工程建议分列；本次不启动付费生成、购买或投稿。

## 1. 话题应实时发现，并保留来源

**平台事实**：[创作话题教程](https://gdce.yuque.com/gksiz6/bp2afo/ad6qnt5gu9gekpmv)将最新话题推荐指向 [创作者中心灵感页](https://creator.huaban.com/inspiration)。语雀这一页自身没有完整话题列表。[话题功能说明](https://gdce.yuque.com/gksiz6/bp2afo/lulydfqo78dyqf6x)还明确区分官方话题和自建话题，一个作品只参与一次活动；若选择多个活动话题，以最后选择者为准。活动评选页说可参与多个活动，应理解为创作者可以分别投稿不同活动，不能据此给同一作品叠加活动收益。

**现状**：客户端 `client.js` 写死五个选项；服务端 `index.js` 从 `pipeline/topics.json` 读固定池；总控 `orchestrator.py` 校验固定话题；采集器 `research_collect.js` 虽访问在线目录，但按固定名称过滤。只改界面仍无法支持新话题。

**建议流程**：点击投稿 → 后端读取配置的实时来源 → 获取全部页/分类/滚动批次 → 去重并形成话题目录 → 界面显示名称、状态、来源、更新时间 → 用户选定 → 再读取每个话题的完整规范与活动期 → 生成绑定稳定平台ID/URL的任务。

应把“灵感推荐”“活动话题”“自建普通话题”分开记录，不能将推荐列表等同于全部活动。页面如仅返回推荐项，应显示采集范围，不写完整。动态来源首次接入仍需实际检查其结构、分页、登录条件与总数；本次只核实教程中的目标链接，未抓取该外部站点的完整话题目录。

话题对象建议字段：`platform_id`、`name`、`url`、`kind`、`source_url`、`fetched_at`、`activity_period`、`rules_url`、`rules_hash`、`availability`、`completeness`。现有英文key作为旧任务兼容别名，不能要求每个新话题手工改代码。

加载失败时保留已选内容；缓存显示采集时间及过期标记；不把旧五项静默当最新完整清单。一次选择多个话题意味着多个独立作品任务，而非同稿挂多个活动。

## 2. 将美观度验收前移到版式设计

**平台事实**：[质量标准](https://gdce.yuque.com/gksiz6/bp2afo/fr75o0cutbee4r54)要求画质、信息、风格、元素、版式、配色、平台审美与差异化共同达标；[创意拓展](https://gdce.yuque.com/gksiz6/bp2afo/hu4vx73a7uxkvgo9)强调真实需求、视觉变量和文案变量。[最新热词](https://gdce.yuque.com/gksiz6/bp2afo/vi488gxah9fk7ogt)强调机会/竞争与低满足度，不能只跟高热度。

**现状**：已有研究、母稿、素材、成稿验收，但流程中只有一个创意方向；`assemble.py` 文本构建字段较少，预览行距未传给PSD，配方若含描边也未完整保留到输出spec；`spec_to_psd.js` 主要传字体、字号、颜色和可选描边。不能在提示词里写了复杂排版就认为原生文字能重现。

**建议**：

1. 在研究中分别记录受众、渠道、核心用途、必须信息、同类供给、差异化切入点。优质参考研究与最新上传查重分开；最新不自动等于优质。
2. 素材生成前先做2—3个低成本原生文字版式草案，比较阅读顺序、主次、对齐、留白与色彩；择一深化，不默认多次付费生整图。
3. 文字契约补齐字重、字距、行高、对齐、段落、旋转、描边/阴影及混排；只开放实际能跨预览、PSD、编辑器一致还原的字段。
4. 字体使用编辑器内可确认版权和可用性的字体；本机预览字体须对应，避免本机宋体、导入后另一字形导致整体气质改变。
5. 用缩略图检查主题识读，用原尺寸检查细节；分别检查文案错漏、人物自然度、材质错误、拥挤程度与局部对比。修改字距/配色/构图后再看实际图。
6. 可让独立审稿Agent提出具体问题，但评分和文件存在不能替代实际视觉判断；没有公开平台分数线，不伪造“平台优质分”。

这些要求应形成可复用的设计skill与渲染实现，单纯扩充提示词不会修复文字样式传递缺失。

## 3. 降低稿豆成本：优先按层创作

**平台事实**：[编辑器易用性](https://gdce.yuque.com/gksiz6/bp2afo/nq8p150hfxrzpoi5)要求完整独立主体、干净背景、可编辑文字与合理编组；[审核避坑](https://gdce.yuque.com/gksiz6/bp2afo/td9amgo07k6gs6la)把背景残留主体、多余图层、不完整元素、过大包围框列为常见问题。平台允许外部AI素材，但来源、授权及证据仍需真实。

**建议双路线**：

| 路线 | 做法 | 适合情形 |
| --- | --- | --- |
| 原生分层创作（优先） | Agent设计版式；文字和形状由本地程序绘制；背景、主体、特殊装饰独立取得/生成；必要时抠图；本地合成PSD | 大字海报、信息模板、小红书封面、票券、套系等 |
| 整图辅助拆层 | 已有母稿 → 分割/抠图 → 遮挡补全 → 文字重建 → 几何还原 → 合成验收 | 复杂写实、材质和遮挡构图，或已有整图修复 |

skill负责识别语义层、决定处理方法、调用工具、写配方和验收；它本身不是抠图或生成模型。文字、色块、圆形、简单装饰可以本地处理；摄影主体、头发蒙版、复杂纹理和被遮挡区域仍需相应模型。按层生成也有光向、视角和风格不一致风险，需要统一素材指导与合成校正，不能承诺天然比整图美观。

图像后端可做可替换接口，统一 `generate`、`edit`、`segment`、`remove_background`、`inpaint`、`decompose`，保留原provider任务ID、请求、模型、费用与下载回执。不同provider不必全支持全部能力，缺能力时明确报错。

候选插件见本次会话调查：`dsh-image-gen` 可接多家服务/订阅/ComfyUI；`dsh-comfyui` 可编排本地或远程流程；`dsh-comfyui-image` 支持去背景但非通用完整多物件分层；Qwen-Image-Layered是需要部署的专门分层模型。以上为文档级候选，未安装或实测。免费插件不代表上游推理免费，已有订阅也受额度和实际权限限制。本机M4/24GB优先验证本地排版和轻量抠图，重型分层的速度、内存、Mac兼容性另测。

继续保留DAM绑定、字体检查、编辑器、投稿等已可用链路；只替换付费出图/拆层环节，不必一次重写全部功能。

## 4. 素材证据应随着后端一起更换

**平台事实**：[声明材料](https://gdce.yuque.com/gksiz6/bp2afo/wrh7rgy4svyxi8kt)要求真实完整记录：AI截图应有工具LOGO、完整关键描述、结果、模型；使用垫图须上传垫图。实拍保留EXIF，手绘/程序素材提供相应创作过程。文字声明、直接把成品当证明、不相符材料都是反例。

**建议**：外部生图插件、本地ComfyUI、本地程序绘图分别生成真实可回溯的证据包。不得把外部生图包装成稿定生成，不得绘制假平台截图或假LOGO；来源接口回执与实际运行界面/记录共同保存，是否满足声明材料要求以平台实际审核为准。

PSD图层直接认证存在平台支持限制。仓库现有的最终PNG登记DAM、绑定真实素材的方向可保留，但“绑定数量相等”只验证映射完整，不证明素材原创或声明已保存。

## 5. 状态、原创路径与多画板需区分

- 创作方式：从零原创/基于现有作品二创。素材版权状态：已认证且无非原创素材/未认证或含非原创素材。两者分开记录。
- 修复已发布原创稿：复用原content ID走重新编辑。套图共用主视觉后续稿：按自己的作品二创路径；不删旧稿重发。
- 多画板不是任意套图都可合并投稿。按多画板专项要求判断长图/PPT等实际形态，不机械补页追求系数。
- 流程状态分成：编辑完成、已投稿、审核中、审核通过/不通过、版权已保存/待核、已交付。交付时保留当时审核状态，不把流程完成写成平台审核通过。
- 活动奖金、下载分成、稿豆是不同单位与资格，按当期规则计算；旧9月“最高1000/持续投稿5000”等不可套用到11月。

依据：[原创/二创路径](https://gdce.yuque.com/gksiz6/bp2afo/okrohsuzflrstvbs)、[多画板投稿](https://gdce.yuque.com/gksiz6/bp2afo/qmceqpf95b6g00gc)、[重新编辑](https://gdce.yuque.com/gksiz6/bp2afo/zpoe10k5fe09bxaa)。

## 6. 建议实施顺序与验收

| 优先级 | 改造 | 验收结果 |
| --- | --- | --- |
| P0 | 动态话题目录与来源/完整性标记，贯通UI、工具、总控与采集 | 页面新增话题无需改代码；加载失败如实显示；旧任务可恢复 |
| P0 | 文字样式契约、字体与预览/PSD/编辑器一致性 | 同一测试稿在三个环节主次、字距、行距、对齐相符，实际看图通过 |
| P1 | 原生分层创作skill与本地渲染，先做一个高文字占比物料试验 | 独立主体、完整背景、可改文字、合成美观；付费任务数量有实际下降 |
| P1 | provider可替换接口与一个替代后端 | 保留任务ID、费用及真实证据；不确定状态不自动重发 |
| P1 | 原创路径、多画板资格、版权材料及真实审核状态 | 操作路径和证据真实可核，不把自检当平台审核 |
| P2 | 复杂母稿分层模型的对照试验 | 同一自有母稿比较质量、耗时、成本、背景补全、透明边缘及可编辑性 |

此处是建议，不表示已授权本次安装或生产投稿。下一轮开发可逐项实现；本次只完成知识沉淀。
