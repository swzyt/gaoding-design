# 插件能力演进笔记

按时间记录的工程细节、踩坑与实测结论，用来解释「为什么这样实现」。
面向使用者的说明看 [插件 README](../dsh-plugin-gaoding-publisher/README.md)，版本变更看 [CHANGELOG](../dsh-plugin-gaoding-publisher/CHANGELOG.md)。

## 全自动为什么一开始要等人工出图（0.39 修复）

DSH 的 `generate_image` 是 **Agent 工具**，插件进程调不到；最初把「DSH 出图」实现成
「插件写素材请求 → 停住 → 等 Agent 出图 → 继续」，于是全自动模式会停在 `waiting-assets`。

实际可行：DSH 图像插件把订阅 OAuth 凭据存在 Host credentials 里
（键名是 `CODEX_OAUTH_1`——配置写 `chatgpt-sub`，底层供应商叫 `codex`），
出图协议固定，插件可以自己发请求：

```
POST https://chatgpt.com/backend-api/codex/images/generations
headers: authorization / chatgpt-account-id / originator: codex_cli_rs
body: { prompt, model: gpt-image-2.6-flare, size }
```

落地实现 `image-client.js`：读凭据 → 过期就用 refresh_token 续（写回原键）→ 出图 →
Pillow 缩放 → **白底自动抠透明**（四角近白才触发 flood fill）→ 写回执。
失败（凭据缺失/请求失败）回落交接模式并在创作状态里记录原因。

踩过的坑：

1. 凭据键名猜成 `CHATGPT_OAUTH_1` 导致 `IMAGE_CREDENTIAL_MISSING`；现在三个候选键依次尝试。
2. 「透明底」判定太松：`min alpha < 255` 就当有透明，结果边缘半透明（min 232）的图被当贴纸，
   投稿前检查要求 `alpha=0` 直接失败。现在 **min ≤ 16 才算真透明**，否则先尝试抠图。
3. 插件热重装会打断正在跑的任务：加了**素材断点复用**（尺寸对得上就复用，不重复花额度）、
   回执增量落盘、中断标记与 `resume:` 续跑。

**实测**：纯白底贴纸 → 透明 PNG；「羊年新春活动有好戏」2 单元全自动跑完并投出
`202483948` / `202494551`，声明均 SUBMITTED，稿豆消耗 0。

## 发布队列与自动调度（0.36 起，0.38–0.39 继续打磨）

**问题**：待投稿任务只能一条条点，投完 12 条要盯半小时；插件重启后进度还丢失。

**实现**（`publish-queue.js`）

- 队列固定串行（同一浏览器空间只能串行），状态原子写入 `runtime/publish-queue.json`；
- 启动时可指定任务，默认取全部「待投稿」；已完成的不重复执行，`pending` 可续跑；
- 单件失败不中断队列，逐条记录原因与原作品 ID；
- 「停止」= 当前这件跑完即停，剩余保持 `pending`，支持续跑；
- 重复启动不会重复执行（in-flight 保护）。

**面板**：结果页出现队列状态条——完成/失败/待投计数、停止、续跑剩余、失败原因摘要；
「全部待投依次投稿」一键启动，运行中每 5 秒刷新进度。

**实测**：12 条素材任务入队，逐件串行执行（每件约 1–3 分钟）。

## 质量门与面板完善（0.35）

**版式质量门（渲染前拦截）**

- 字号下限 24px；字号层级 ≤4 档；主标题至少是正文的 1.6 倍；
- 文字与所处纯色层对比度：大字号 ≥3:1、小字号 ≥4.5:1（WCAG 相对亮度算法）；
- 纯色 `shape` 装饰层直接丢弃——它们最容易看起来像渲染错误，装饰交给素材图。

配套把规则写进配方提示词（第 8–13 条），并保留原有门：安全边距、背景铺满、主体 ≤35%、图层 ≤16、除容器外不得压文字。

**面板**

- 结果页：勾选任务后「批量投稿 / 批量取消」；运行中的任务显示当前步骤与已耗时；
- 已投稿页：状态徽标可直接点击筛选、按时间/浏览/下载排序、导出 CSV、每行「详情」跳转平台。

**实测**

- 同一单元重跑排版后：标题/副标题/正文层级清晰、主体位于卡片上方留白处、无杂色块、无压字；
- `publish/cancel` 对未开始任务生效（状态变 `cancelled`），已开始/已发布拒绝；
- `publish/batch` 逐条返回 `started/skipped` 与跳过原因（已取消、任务不存在等）。

**仍未做**

- 模板声明的逐层精确分类（AI 图 vs 程序图形）：平台候选按内容去重且预览图重编码，
  目前策略是「含 AI 图层的模板整稿声明原创 AI 素材」。彻底方案需要 DAM 素材 ID 映射，
  实测内容 JSON 的元素不带 `dam_id`，只能靠声明记录里的 `dam_id`，缺映射链路，暂缓。
- 单件模板发布仍需 4–6 分钟（编辑器导入 + 渲染 + 声明会话）。

## P1 功能与两条链路端到端验证（0.32–0.34）

**新增能力**

1. **批量投稿**：结果页勾选待投任务 → 一次串行提交（同一浏览器空间本来就只能串行），跳过已发布/已取消/执行中的任务并回报原因。
2. **取消**：未开始的任务可取消（`cancelled` 状态），已开始的只能等它跑完，避免半截投稿。
3. **运行时状态持久化**：投稿/自动链路状态落盘 `runtime/publish-runs.json`；重启后把「仍在运行」的标成 `interrupted`，不再静默丢失。
4. **素材稿也能走 DSH 出图**（后端选项 `DSH 出图（0 稿豆）`）：与模板同一套素材交接协议，生成后落地为 `material.json`。
5. **模板补声明通道** `publish/republish`：平台确认该作品没有声明记录后，撤销旧作品、归档记录、按新流程重发（声明在发布会话内完成）。

**端到端实测（均为 0 稿豆）**

| 链路 | 结果 |
|---|---|
| 模板（`小红书创意plog`） | 作品 `202490383`：纸纹背景 + 信息卡 + 3D 小羊 + 9 个原生文字层 → 发布 → 声明面板 6 个候选全归「原创 AI 素材」→ 证据上传 → 平台回读 6 条 `ORIGINAL_AI` |
| 素材（`美妆个护上新背景`） | 作品 `202485405`：DSH 出图 941×1672 → 声明面板单区上传证据 → `declaration-verified: SUBMITTED` → 详情页话题核验通过 |

**本轮暴露并修掉的缺陷**

1. 跨域 canvas 污染导致候选指纹读不到（`drawImage` 后 `getImageData` 抛安全错误）→ 改成 fetch blob + `createImageBitmap`。
2. 两侧指纹算法不一致（Pillow 忽略 alpha、浏览器透明当黑）→ 统一垫白底后再算。
3. 调用方算好的声明计划被内部重算覆盖，感知哈希丢失 → `publishTemplate` 优先使用传入计划。
4. 单分类场景没执行「移动至」，候选一直留在未分类 → 把归类步骤提到分组外统一执行。
5. 单分类分支漏设 `pickedAny`，误报「没有可归类的候选」→ 补上。
6. `withdrawContent` 缺省 `spawnProcess`，路由直接调用报 `spawnProcess is not a function` → 补默认值。
7. 素材稿把 RGBA 一律当透明素材，检查要求 `alpha_range` 而记录为空 → 用真实 alpha 范围判断。
8. 模板声明分类策略：逐张区分 AI 图/程序图形太脆弱（平台去重 + 重编码）→ 含 AI 图层的模板整稿声明「原创 AI 素材」，纯程序绘制才声明「原创素材」。

## 模板质量：从「纯色块」到「真实图像层」（0.29–0.31）

**问题**：模板稿只有 `shape` + `text` 两类层，`prompt.json` 里规划的素材（纸张纹理、手绘贴纸、人物、信息卡）全部被丢弃，
渲染出来就是一堆矩形。实测一稿里 3 个满画布不透明层互相覆盖、形状与文字框相交 78 处。

**方案**：模板改用「出图后端生成素材 + 本地渲染合成」，全程不消耗稿豆。

1. **素材交接协议**（`asset-handoff.js`）：插件按 `prompt.assets` 写出
   `generated-assets/request.json`（素材 id、prompt、目标尺寸、是否要透明底、token）；
   Agent 用 DSH 出图插件生成后写 `generated/<id>.png` 与 `response.json`（路径、sha256、尺寸、是否有 alpha）；
   插件校验：文件存在、路径不越界、哈希一致、`require_alpha` 必须有 alpha 通道、短边 ≥512。
   没回执时创作明确报 `ASSETS_WAITING`，面板显示「等待出图素材」，**不会偷偷退回纯色块**。
2. **配方支持图像层**：`type:"image"` + `source:"generated/xxx.png"`；文字层强制排在最上层；
   渲染前校验素材文件真实存在；`generated/` 下的图层自动按「原创 AI 素材」声明。
3. **版式硬门槛**（`layoutProblems`）：文字必须在 60px 安全边距内（超了自动收进来）；
   背景必须铺满画布；主体面积 ≤35%；装饰 ≤4%；图层数 ≤16；
   除容器外，任何层压到文字直接拒绝渲染。
4. **混合来源声明**：一稿里同时有 AI 图与程序图形时，按图层哈希匹配平台候选（不是按顺序猜），
   分组归入「原创 AI 素材」与「原创素材」，两类各上传一次声明材料。

**实测**（`chatgpt-sub` / `gpt-image-2.6-flare`，0 稿豆）：3 张素材一次生成成功，
其中主体图**直接输出透明底 PNG**（33% 像素为透明），不需要抠图。

- 纸纹背景 + 磨砂信息卡 + 3D 黏土小羊 + 9 个原生文字层 → 15 层 PSD，投稿前检查通过；
- 声明计划自动分成两组（程序图形 / AI 图），候选按哈希对齐。

## 素材投稿「发布成功但声明失败且不重试」（0.25.0 修复）

**现象**：新任务投稿后进入「结果不确定」，作品其实已经发出去了，但逐层版权声明没做，流程停下不动，也不会自动重试。

**根因**：0.24.0 我给素材套用了模板的分类逻辑，要求声明面板里出现 `.ugc-copyright-section`
（未分类/原创/AI 分区）。实测两类面板结构不同：

- 模板：`未分类素材 / 稿定素材 / 原创素材 / 原创 AI 素材 / 非原创素材` 五个分区，需要先选候选、再「移动至」分类；
- 素材：只有一个「素材」区 + 「声明材料」上传框，**没有分类区**，AI 属性由发布时的「含AI生成内容」开关承载。

所以素材声明在「版权声明分区没有渲染出来」处必然失败，而作品已经发布。

**修复**：

1. 声明面板自适应：检测到分类区走分类流程，检测不到就走单区上传流程；
2. 声明提交后用平台接口 `/users/me/materials/<id>/declaration` 核验 `material_declaration_status`，
   面板还开着时失败会原地重试一次；不通过才判失败，不再「点了按钮就算成功」；
3. 声明未完成时写 `published-pending-declaration`（含作品 ID 和待声明证据路径），不再笼统报「结果不确定」；
4. 运行级自动重试：只要没有真的发出去（无作品 ID、无既有发布记录），浏览器偶发失败会自动再跑一次，
   失败步骤记 `retry:N`；已发布的一律不重试，只走声明恢复，避免重复投稿。

**遗留（需人工一步）**：`202476167`（羊年文创印出新花样）就是这次失败的作品，作品已发布、
声明待补。详情页「原创声明」面板的文件选择控件只认真实用户选择，CDP 注入文件无效，
自动化补不了；手动打开该面板点「声明材料」上传
`runs/job-20261117142610-7c9a47-ec2ae7-1/publish/ai-evidence.png` 即可完成。
新流程已不会再产生这种状态。

## 已投稿稿仍显示「检查未通过」与全自动不投稿（0.23.x 修复）

**现象一**：素材已经投稿成功，面板还红字显示「投稿前检查未通过」。
原因：检查项最后一条是「尚未投稿（不重复提交）」，稿件发布后这条必然不通过；
面板只按 `ok` 判断成败，于是把「已投稿终态」渲染成失败。
修复：检查结果新增 `published / status`，已投稿的稿子最后一条显示「已投稿（不会重复提交）」，
面板显示「已投稿，无需再次提交」并隐藏创建任务按钮；接口返回 `published: true`。

**现象二**：全自动模式只创作不投稿。
原因：自动链路在创作完成后就停在「待投稿」，投稿是另一条手动入口。
修复：自动链路改为创作全部成功后立即逐单元做投稿前检查 → 建投稿任务 → 真实投稿 → 读持久记录核验；
已完成（含声明核验）的单元跳过，历史未完成只走恢复不重发，素材「结果不确定」时停下要求对账；
已投稿但无任务记录的稿件标 `published-unmanaged` 并跳过，不重复投稿。

**现象三**：模板发布完成后没有任何声明。
原因（实测）：模板的逐层声明只在「发布成功 → 去完善」这一个页面会话里可用；
从「我的-发布 → 更多 → 版权认证」打开时，平台对这些模板返回「当前没有需要确权的素材」，
接口 `/api/v3/cp/ugc/contents/<id>/copyright-declarations` 为空。
修复：声明必须在发布会话内完成，且不允许「先发布、声明以后再说」：

1. 发布前生成声明计划：图片层数、平台去重候选数（按文件 sha256 去重）与真实证据三者必须对齐，缺一层直接失败；
2. 声明材料图为逐层证据：列出全部图片层的真实缩略图与哈希（21 个图片层 → 15 个平台候选）；
3. 发布会话内：发布成功 → 点「去完善」→ 选中候选（批量工具栏出现后「全选」）→「移动至」目标分类
   → 上传声明材料 → 勾选知悉 →「声明并发布」；
4. 提交后用平台接口真实回读，要求记录条数覆盖全部候选，否则整条投稿判为未完成。

实测（小红书创意plog，21 个图片层 / 6 个原生文字层 → 平台 15 个候选）：

- 作品 `202453954`，话题「小红书创意plog」，审核中；
- 声明面板 15 个候选全部归入「原创素材」，声明材料上传成功，提交保存；
- 平台回读：15 条记录，全部 `ORIGINAL`，各带 1 个证据地址，`verified: true`。

## 插件模板稿为什么不能投稿（0.21 修复）

现象：小红书备忘录的模板稿点「创建投稿任务」直接失败。

原因：投稿前检查只认仓库原生工作流的产物（`run.json` + 04-final 门 + 逐层隐藏审计 + `copyright-evidence.json`）。插件自己生成的模板稿是另一套产物：`creation.json` + `release-recipe.json` + `release/`（PSD、预览、图层清单）。两边格式不同，检查在第一项就判「缺少 run.json」，任务创建被拦。

修复内容：

1. 新增插件模板稿检查 `checkTemplateRun`，只检查真实可验证的部分：创作记录、配方图层、图层 ID 唯一、文字为原生文字、图层不越界、PSD/预览/清单存在、清单文件哈希、以及**只允许程序原创**（出现外部/AI 图片层立即失败，因为需要按层版权证据）。
2. 原生文字层在清单里是 `editable_text`、没有 PNG 文件，检查不再把它当作缺失文件。
3. 投稿说明按稿件来源分流：插件模板稿用编辑器导入+发布的说明，不再给需要 04-final 门的 `browser-batch` 命令。
4. 模板投稿真正接入了运行链路：先 `browser prepare` 把 PSD 导入编辑器取得设计地址，再在编辑器内「发布」。
5. 修两个导入相关的 bug：调用导入时漏传插件的运行时环境（导致 `Dependencies missing`）；编辑器 SPA 偶发空白页时整页重载重试，最多 3 轮。

实测（小红书备忘录，41 层 = 27 图片层 + 14 原生文字层）：

- 投稿前检查 9 项全部通过，投稿任务成功创建 `pub-20261117133016-9ce0b5`；
- 演练跑通：`fonts-confirmed → modal-opened → description-filled → topic-selected:37720293698033698 → topic-verified`；
- 编辑器生成设计 `38651465426134123`（导入 41 层），发布弹窗话题精确挂到「小红书备忘录」，AI 开关保持关闭（程序原创）。

平台对模板不强制逐层版权声明，插件仍记录 `declarationStatus: NOT_REQUIRED_BY_PLATFORM` 并提示可发布后完善；真实提交需在面板点「开始投稿」。

## 故障记录：页面配额耗尽导致投稿失败（0.20.2 修复）

2026-11-17 21:14，三条「羊年祝福玩梗有一套」素材投稿同时失败，面板显示「结果不确定」。实际原因不是平台或素材问题：

- 报错：`Page budget reached (8/8) in space "稿定投稿-…"`。
- 根因：投稿脚本每次运行新开 2 个页面（校验页、发布弹窗页）却从不关闭；几轮之后空间 8 个页面配额占满，后续运行连第一个页面都开不出来。
- 三份提交日志都是 `published:false / content:null / steps:[]`，且平台发布列表 13:05 之后没有新增作品——**确认一件都没发出去**，不存在重复投稿风险。

修复与控制：

1. 脚本在 `finally` 中关闭自己打开的每一个页面，空间页面数长期维持在 1。

## 登录态怎么处理

- 不收集账号密码。稿定登录是 OAuth，登录态是页面 `localStorage.token` 里的 Bearer 令牌。
- `POST /session/probe` 用该令牌请求话题接口：`200` 记为已登录，`401` 记为未登录，令牌过期单独标记。
- `POST /session/login` 打开创作者中心页，由你扫码/短信/密码自行完成登录，再点「检查登录」。
- 登录信息只写 `catalog/session.json` 的 `space / loggedIn / account.id / checkedAt`，不写令牌本身。

### 创作分两轮：先写 prompt，确认后才出图

1. **建任务**：按数量从规范方向里分发，每单元一份「创作要求」（画布、方向、禁区、物料、用户备注），冻结进 `topic.json` 的 `brief`。
2. **写 prompt（不花钱，自动）**：建任务后插件直接调用宿主 `ctx.llm`（默认模型）逐单元生成 prompt，写进单元目录的 `prompt.json`，带分层计划 `layers[{id,role,require_alpha}]`。面板显示生成进度，失败可一键重试；也保留 `gaoding_prompts action=write` 作为 Agent 手写备用路径。
3. **用户审核**：面板显示每个单元的 prompt，可原地修改。修改会让 `revision+1` 并**作废已有确认**。
4. **用户确认**：面板「确认 prompt 并允许出图」，只有用户能确认；Agent 的工具没有确认动作。
5. **执行**：确认后指令才包含 `auto` 参数与冻结的 `prompt.json` 路径，Agent 按 prompt 出图并分层；未确认时指令只允许写 prompt。

| 接口 / 工具 | 用途 |
| --- | --- |
| `GET /gaoding-publisher/prompts?job=` | 单元 prompt 与当前状态 |
| `POST /gaoding-publisher/prompts` | 用户编辑某个单元的 prompt（作废确认） |
| `POST /gaoding-publisher/prompts/confirm` | 用户确认整单（所有单元都写完才允许） |
| `gaoding_prompts action=list` | Agent 读待写/待确认的任务 |
| `POST /gaoding-publisher/prompts/generate` | 调模型重新生成 prompt（`{jobId, force}`） |
| `gaoding_prompts action=write` | Agent 手工写入单元 prompt（备用路径） |

### 为什么点一下不会自己开跑

DSH 里只有两种方式启动模型轮次：用户消息，或 Agent 的工具调用。界面点击不能直接创建轮次，插件也不会偷偷开子 Agent——那会在用户没有确认的情况下启动付费生成。所以执行入口是：

1. 面板里建任务（冻结话题与参数）；
2. 把「执行指令」发给对话里的 Agent，或直接说「执行任务」；
3. Agent 调 `gaoding_jobs` 认领，再用 `gaoding_workflow` 逐个单元执行；
4. 面板轮询任务与结果，实时显示真实阶段。

## 创作执行入口（0.12）

素材话题在 prompt 确认后，面板会出现「开始创作（生成本单元素材图）」：

1. 点按钮先做 dry-run：显示模型、单张稿豆区间、账户余额、每单元实际画布与 prompt；
2. 你点「确认生成」才真正调用 `gd-cli tool call image.generate`（会消耗稿豆）；
3. 结果下载 → 转 PNG → `sips` 读尺寸与 alpha → 运行时 Pillow 读真实 alpha 范围 → 写 `material.json`；
4. 素材出现在「结果与投稿」，可走投稿前检查与素材投稿任务。

| 接口 | 用途 |
| --- | --- |
| `GET /gaoding-publisher/create/status` | gd-cli 是否可用、登录态、稿豆余额、模型价格 |
| `GET /gaoding-publisher/create/preview?job=` | dry-run：每单元的模型/画布/prompt，不产生费用 |
| `POST /gaoding-publisher/create` | `{jobId, model, confirm:true}` 才执行；模板话题返回 409 |

模板话题的「开始创作」走另一条路：**模型写分层配方 → 本地 `workflow build` 渲染**，不生成整图、不消耗稿豆，文字保持原生可编辑。

- 配方由模型产出，程序只做规整：固定使用 `STHeitiSC-Medium` 字体、box 裁进画布、字号下限 12、自动补满画布背景层；
- JSON 有语法错误时自动让模型修复一轮，两次尝试都存 `recipe-attempt-N.txt`；
- 产出 `release-recipe.json`、`release/`（PSD、preview.jpg、layer-manifest、materials.zip）与 `creation.json`，出现在「结果与投稿」；
- 纯原生模板没有 AI 母稿，`assemble.py` 的 `reference/master.jpg` 已改为可选。

模板还没做的一步：把 PSD 导入编辑器、逐层字体与隐藏验收、随后投稿——这一步仍需要 Agent 或后续接入 `gd-cli editor`。

| 话题 | `/api/gaoding-art/v1/contents/versions/latest` 的 `topics`（含 applicable_publish_type） |

面板支持按状态、模板/素材、标题或话题筛选；顶部汇总总数、浏览、下载、编辑器使用次数与状态分布。

**数据现状（实测）**：17 件作品，14 审核中 / 3 已通过，浏览 36、下载 20；9 件有统计字段，其余为空（平台未给数）。话题只在有版本的稿件上返回。

## 手动 / 全自动模式（0.16）

创建任务时选择执行模式：

| 模式 | 行为 |
| --- | --- |
| 手动（默认） | 生成 prompt → 等你确认 → 你再点「开始创作」；每一步都由你推进 |
| 全自动 | 生成 prompt → **按 auto-policy 自动确认** → 自动创作 → 进入「待投稿」，中途不需要点击 |

自动模式的确认会写进 `prompt.json` 的 `confirmedBy: "auto-policy"`，事后可追溯是谁（策略还是人）放行的。

流水线状态通过任务字段返回：

```json
{"running": false, "stage": "ready-to-publish",
 "steps": ["prompt-written","prompt-confirmed:auto-policy","created:1/1"]}
```

**边界**：自动模式目前覆盖 `prompt → 确认 → 创作`，停在「待投稿」。投稿要操作编辑器/发布弹窗，需要 `gaoding.com` 的 SSO 登录态；登录后可把导入、逐层核验、提交、版权声明也接进同一条自动链。

## 素材投稿执行、AI 证据与话题校验（0.18）

**执行入口**：每个投稿任务有「演练（不发布）」和「开始投稿」，实际驱动浏览器完成
发布弹窗 → 本地上传 → 填描述 → 关联话题 → 勾选含AI生成内容 → 提交，并逐步记录与截图。

**AI 生成证据图**：`ai-evidence.py` 把「话题 / 生成方式 / 模型 / 工具 / 生成时间 / 画布 / 文件 / SHA256 / 完整 prompt / 结果预览 / 声明文案」渲染成一张 1600×2200 的说明图，落盘到 `<run>/publish/ai-evidence.png` 并附同名 JSON。接口 `GET /publish/evidence/ai?task=`；投稿执行前会自动生成。

**话题校验**：发布成功后回读发布管理，比对作品的 topics 是否等于任务话题；不一致时记 `topic-mismatch`，不当作成功。

**已确认的平台事实**：
- 作品详情页 `https://gd.huaban.com/my/publish/<contentId>` 有「原创声明：未进行原创声明」与「商用授权信息填写」；
- 素材发布后状态为 `WAITING_MATERIALS`（等素材版权声明）；
- 发布弹窗在 `gd.huaban.com/applink/popup/unified-publish-modal` iframe 内，话题 chip 只在推荐列表里出现，非推荐话题需要通过「更多 → 搜索话题」，该下拉与 iframe 叠层存在点击拦截，仍在解决。

### 已验证的生产路径（0.19）

1. 创作者中心点「发布」→ 读取弹窗 iframe 地址；
2. **把弹窗地址当独立页面打开**，用 DOM 操作（不再被 iframe 叠层拦截）；
3. 上传素材 → 填描述 → 「更多 → 搜索话题」→ 点 `button[data-topic-candidate-id]` 精确选话题；
4. **话题必须出现 `span[data-topic-id]` 内联 token 才算挂上**，纯文本包含不算；
5. 勾选「含AI生成内容」→ 发布素材 → 出现「发布完成」；
6. 点「去完善」→ 版权声明页上传 `ai-evidence.png` → 勾选知悉 → 声明并发布；
7. 回读发布管理：`material_declaration_status = SUBMITTED`，作品详情页 topic chip 与任务话题一致。

实测两件作品通过：`202453078`（特效系列光效素材）、`202471439`（羊年新春活动有好戏），话题 chip 正确、声明 SUBMITTED。

### 模板投稿已验证可行（手工路径，0.19.2 记录）

实测完整走通一次模板投稿：

1. `workflow.sh browser prepare <recipe> --space <id> --page p1` 把 PSD 导入编辑器（21 层）；
2. 编辑器有「字体确认」弹窗（STHeitiSC-Medium → 思源黑体 常规），必须点确认；
3. 编辑器点「发布」打开 **scene=editor** 的弹窗；**该弹窗不能独立打开**（需要和编辑器通信），
   必须在编辑器页面里用无障碍快照 ref 操作 iframe 内部；
4. 弹窗里填描述 → 「更多 → 搜索话题」选到「小红书大字封面」（描述里出现话题 token）→ 点「发布」；
5. 出现「发布成功」，发布管理里得到 `contentId 202456563`，`publishType=0`（模板），
   详情页话题 chip = 小红书大字封面，审核中。

模板版权声明弹窗结构：21 个图层以「未分类素材」列出，可拖到「原创素材 / 原创 AI 素材 / 非原创素材」，
每类可上传「声明材料」，最后勾选知悉并「声明并发布」。**尚未自动化**。

### 模板投稿的早期探索结论（已被上面取代）

- `workflow.sh browser prepare <recipe> --space <id> --page p1` **能把模板 PSD 导入编辑器**：实测导入 21 层（`背景-完整底色`、`主标题`、`书堆底层` 等），并生成设计 `38651026882684001`；随后脚本在等待编辑器就绪时超时，说明导入成功但后续等待需要调整。
- 编辑器里点「发布」会打开 `scene=editor` 的发布弹窗，初始文案是「模板共创计划」，但上传封面后弹窗又切到「发布素材」，说明**模板发布不能靠上传封面**，必须走编辑器自身的模板发布路径。
- 结论：模板投稿的自动化应以「编辑器内发布」为目标，而不是发布弹窗上传；下一轮聚焦这一点。
